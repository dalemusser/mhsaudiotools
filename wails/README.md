# wails/ — the desktop app

The Wails v2 app the art/game team actually uses. Like `cmd/cli`, it is a **thin
shell** over `engine/` — `app.go` only validates input, calls the engine, and
shapes results for the UI. No dialog or audio logic lives here.

## Why this is a separate Go module

Both modules target Go 1.25. The reason for the split is dependencies, not the
Go version: Wails pulls in ~30, while `engine/` and `cmd/cli` deliberately have
**zero** third-party dependencies, and keeping that true is worth more than a
single `go build ./...`. So this directory is its own module that `replace`s the
engine to `../` (same repo, still one checkout).

Consequence: `go build ./...` at the repo root does **not** include this app.
Build it from here.

## Prerequisites

- Go (a 1.25 toolchain is fetched automatically if needed)
- Xcode command line tools (macOS)
- The Wails CLI: `go install github.com/wailsapp/wails/v2/cmd/wails@latest`
- **No Node/npm.** This uses the `plain` template — hand-written HTML/CSS/JS.

## Tasks

```bash
make setup   # download the Tailwind standalone CLI (once per machine)
make css     # compile frontend/tailwind.css -> frontend/src/app.css
make watch   # recompile CSS on change
make dev     # run with hot reload
make build   # produce build/bin/aigenaudio.app
```

`frontend/src/app.css` is **committed** so the app builds without the Tailwind
binary; only re-run `make css` if you touch markup or `tailwind.css`.

## Layout

```
main.go                 window options + Bind(app)
app.go                  the bound methods (the entire JS<->Go surface)
frontend/tailwind.css   Tailwind source (edit this)
frontend/src/
  index.html            the UI
  main.js               UI logic; calls window.go.main.App.*
  app.css               GENERATED by `make css`
frontend/wailsjs/       GENERATED bindings (wails build/dev writes these)
frontend/.tools/        the Tailwind binary (gitignored)
```

## Notes

- **No HTMX, and no localhost server.** We use Wails' default binding model
  (`window.go.main.App.*`), so there are no URLs for HTMX to talk to — a server
  on a user's machine is exactly the support burden this app exists to avoid.
  Tailwind still applies; the JS is plain and small.
- Progress streams to the UI via the Wails event bus (`runtime.EventsEmit` →
  `window.runtime.EventsOn("progress", …)`).
- The API key comes from `$ELEVENLABS_API_KEY` or `~/.elevenlabs_key`
  (`engine/keys`); the UI offers to save one if neither exists.
